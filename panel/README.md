# CS2 Panel — веб-панель сервера CS2 на Node.js

Браузерная панель на Express:

- **Сервер**: статус (карта, игроки, пинг, версия), таблица игроков со ссылками на Steam-профили,
  быстрые действия (рестарт раунда, пауза, смена карты, сообщение в чат, боты, `exec cfg`), RCON-консоль.
- **Скины**: каталог скинов с фильтрами и сортировкой (справочник/вишлист — **без** вмешательства в игру).
- **Сборки**: сохранение сборок скинов **по вашему SteamID** (вход через Steam OpenID), публичные сборки.
- **Настройки**: список серверов (несколько RCON-серверов в одной панели).

> Панель работает только с официальным RCON протоколом Source и Steam Web API.
> Никаких внедрений в процесс игры, никаких правок файлов CS2, никаких обходов VAC.
> Клиентский скинченджер/читы сюда не входят и не войдут: это бан и вред другим игрокам.

## Запуск

```bash
cd panel
npm install
cp .env.example .env    # заполните
npm start               # http://localhost:3000
```

Разработка с автоперезапуском:

```bash
npm run dev
```

## Настройка (.env)

| Переменная | За что отвечает |
|---|---|
| `PORT`, `HOST` | где слушает панель (`HOST=0.0.0.0` для доступа извне) |
| `PUBLIC_BASE_URL` | публичный адрес панели — обязателен для Steam OpenID |
| `SESSION_SECRET` | подпись сессий, сгенерируйте свой |
| `STEAM_API_KEY` | ключ <https://steamcommunity.com/dev/apikey> — нужен только для имён и аватаров |
| `ADMIN_STEAM_IDS` | SteamID64 админов панели через запятую (доступ к RCON) |
| `ALLOW_SERVER_MANAGEMENT` | можно ли добавлять серверы из интерфейса |
| `CS2_RCON_HOST/PORT/PASSWORD` | сервер по умолчанию (остальные добавляются из панели) |
| `DEMO_MODE` | `1` — показывать демо-данные даже при настроенном сервере |

Без `CS2_RCON_HOST`/`CS2_RCON_PASSWORD` панель стартует в демо-режиме: интерфейс живой,
но данные выдуманы, а команды не отправляются (в ответе приходит `demo: true`).

Для локальной демонстрации есть `DEMO_ADMIN=1` (работает только вместе с `DEMO_MODE=1`):
панель пускает вас сразу админом под учебным SteamID, без входа через Steam.
На боевом сервере так делать не надо — задайте реальные `ADMIN_STEAM_IDS`.

## Как это работает

```
Браузер  ──HTTP──▶  Express (panel/src/app.js)
                      ├─ /api/status, /api/console, /api/action ──TCP──▶ RCON сервера CS2
                      ├─ /api/skins, /api/skins/weapons ──▶ data/skins.json (или skins.sample.json)
                      ├─ /api/loadout ──▶ data/store.json (ключ — SteamID64)
                      └─ /auth/steam ──▶ Steam OpenID 2.0 ─▶ Steam Web API (имя, аватар)
```

Ключевые модули:

- `src/rcon.js` — клиент Source RCON без зависимостей + парсер вывода `status`
  (поддерживает SteamID форматов `[U:1:…]`, `STEAM_x:y:z`, ботов).
- `src/steam.js` — Steam OpenID 2.0 (`checkid_setup` → `check_authentication`) и подписанные HMAC-сессии.
- `src/store.js` — JSON-хранилище (серверы, сборки, профили) с атомарной записью.
- `src/skins.js` — загрузка и фильтрация каталога скинов.

## API

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| GET | `/api/health` | все | состояние панели |
| GET | `/api/config` | все | публичные настройки |
| GET | `/api/session` | все | текущий пользователь |
| GET | `/auth/steam` | все | редирект на вход через Steam |
| GET | `/api/servers` | админ | список серверов |
| POST/PATCH/DELETE | `/api/servers[/:id]` | админ | управление серверами |
| GET | `/api/status?serverId=` | админ | статус и игроки |
| POST | `/api/console` | админ | команда в RCON (опасные — с `confirm`) |
| POST | `/api/action` | админ | готовые действия: `restart`, `map`, `say`, `kick`, `bots`, `pausematch`, … |
| GET | `/api/skins` | все | каталог скинов (`query`, `weapon`, `rarity`, `sort`, `page`) |
| GET/POST/DELETE | `/api/loadout[/:id]` | вошедший | сборки текущего SteamID |
| GET | `/api/loadout/public` | все | публичные сборки |

## Данные

- `data/skins.sample.json` — демо-каталог (~90 скинов). Положите свой `data/skins.json`
  с тем же форматом — панель подхватит его при старте.
- `data/store.json` — серверы, сборки, кэш профилей. Создаётся сам, в git не коммитится.

## Безопасность

- RCON-пароли не отдаются на фронтенд (в ответах только `hasPassword`).
- Управление доступно только SteamID из `ADMIN_STEAM_IDS`.
- Опасные команды (`rcon_password`, `quit`, `_restart`, …) требуют подтверждения.
- Сессии — cookie с HMAC-подписью, `httpOnly`, `secure` при https.
- Снаружи панель лучше публиковать за HTTPS (nginx/Caddy) и ограничить по IP.
- Учётные данные и пользовательские данные не попадают в git (см. `.gitignore`).
