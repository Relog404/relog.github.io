# CS2 Panel — сайт на Node.js: сервер CS2, каталог скинов, апгрейд, магазин

Одно приложение на Express, которое поднимается на выделенном сервере и закрывает четыре задачи:

1. **Сервер** — RCON-управление выделенным сервером CS2: статус, игроки, карты, чат, консоль.
2. **Каталог** — витрина скинов CS2 (ножи, перчатки, винтовки, пистолеты, снайперки, ПП, дробовики, стикеры, медали, значки, кейсы, музыка, патчи, агенты) c поиском, фильтрами и вишлистом.
3. **Экономика** — виртуальные монеты, магазин, хранилище предметов и **апгрейд-рулетка** с честным RNG.
4. **Админка** — статистика, игроки, правки каталога, история розыгрышей.

> **Политика проекта, читать обязательно.**
> Монеты виртуальные: их нельзя купить за деньги, пополнить реальными предметами из инвентаря Steam
> и вывести обратно. Никаких депозитов, реальных ставок и кэшаута — только фановый режим.
> Скинченджеров, «худов» и любых вмешательств в игровой клиент здесь нет и не будет:
> это VAC-бан и порча игры остальным.

## Запуск

```bash
cd panel
npm install
cp .env.example .env    # заполните
npm start               # http://localhost:3000
```

Разработка: `npm run dev`. Тесты: `npm test`.

## Настройка (.env)

| Переменная | За что отвечает |
|---|---|
| `PORT`, `HOST` | где слушает панель (`HOST=0.0.0.0` для доступа извне) |
| `PUBLIC_BASE_URL` | публичный адрес панели — обязателен для Steam OpenID |
| `SESSION_SECRET` | подпись сессий, сгенерируйте свой |
| `STEAM_API_KEY` | ключ <https://steamcommunity.com/dev/apikey> — имена и аватары |
| `ADMIN_STEAM_IDS` | SteamID64 админов панели через запятую (RCON + админка) |
| `ALLOW_SERVER_MANAGEMENT` | можно ли добавлять серверы из интерфейса |
| `CS2_RCON_HOST/PORT/PASSWORD` | сервер по умолчанию |
| `DEMO_MODE` / `DEMO_ADMIN` | демо-данные и демо-вход админом без Steam |
| `START_COINS` | стартовый баланс нового игрока (по умолчанию 1000) |
| `DAILY_COINS`, `DAILY_COOLDOWN_HOURS` | ежедневный бонус (250, раз в 20 ч) |
| `UPGRADE_EDGE` | коэффициент апгрейда: `шанс = ставка / цена цели * edge`, по умолчанию 0.95 |
| `CURRENCY` | валюта отображения цен: `coins` (монеты 🪙), `rub` (рубли ₽), `usd` (доллары $) |
| `RATE_RUB` / `RATE_USD` | сколько рублей/долларов в одной монете (по умолчанию 1 и 0.011) — только для отображения |
| `COIN_RATE_RUB` | сколько рублей в одной монете: цена со Steam в ₽ делится на это число (по умолчанию 10) |
| `CASE_EDGE` | цена кейса = математическое ожидание дропа × `CASE_EDGE` (0.95) |
| `PRICE_SYNC_*` | синхронизация реальных цен со Steam: `ENABLED`, `DELAY_MS`, `BATCH`, `HOURS` |
| `USD_RUB` | курс доллара для пересчёта цен Steam в доллары (95) |
| `SELL_RATE` | доля цены при продаже предмета обратно (0.85) |

Без `CS2_RCON_HOST`/`CS2_RCON_PASSWORD` панель стартует в демо-режиме: интерфейс живой,
данные выдуманы, команды не отправляются (`demo: true` в ответе).

## Как устроена экономика

- **Монеты** начисляются за старт (`START_COINS`) и ежедневный бонус, тратятся в магазине.
- **Магазин**: покупка любого предмета каталога за монеты → предмет уходит в хранилище.
- **Хранилище**: ваши предметы; можно продать обратно за `SELL_RATE` от цены.
- **Реальные цены Steam**: админка → «Цены Steam» → «Обновить цены». Панель ходит в публичный
  `steamcommunity.com/market/priceoverview` (appid 730), собирает точное имя лота
  (`★ StatTrak™ Karambit | Fade (Factory New)`), берёт `lowest_price` и перекрывает базовую цену
  каталога. Порциями, с паузой, переживает 429; прогресс виден в админке, всё можно сбросить.
- **Валюта цен**: монеты остаются внутренней единицей, но показывать цены можно в рублях или долларах.
  Переключатель валюты — в шапке сайта (выбор сохраняется в браузере), значение по умолчанию и курсы
  задаёт админ в «Админка → Валюта сайта» (`PATCH /api/admin/settings`).
- **Кейсы** (отдельный режим): 14 кейсов (ножи, перчатки, винтовки, стикеры, брелоки, музыка,
  коллекционное, «всё подряд» и др.). Цена кейса считается из наполнения — ожидание дропа × `CASE_EDGE`,
  шансы считаются по редкости и цене (`weight = rarity × (max/price)^0.35`), приз падает в хранилище.
- **Апгрейд**: ставите один или несколько предметов (сумма = ставка), выбираете цель.
  Крутится колесо: размер зелёного сектора = ваш шанс, стрелка делает 5–7 оборотов и останавливается
  по `roll`; попали в зелёное — цель ваша.
  Шанс = `(ставка / цена цели) × коэффициент`, ограничен диапазоном 1%…95%.
- **Пресеты множителей**: кнопки `×2 ×4 ×8 ×10 ×25 ×50` подбирают цель, которая дороже
  ставки в N раз. Множитель — это «во сколько раз цель дороже», шанс считается от него.
- **Настраиваемые базовые шансы**: в админке у каждого множителя свой коэффициент
  (x2 → 0.9785, x50 → 0.8075 по умолчанию). Меньше коэффициент — ниже шанс и больше маржа.
  Меняются на ходу, без перезапуска.
- **Сервер CS2 не обязателен**: сайт, магазин и апгрейд работают без игрового сервера.
  Привязка нужна только чтобы плагин забирал надетые скины в игру (`serverRequired: false`).
  Выиграли — цель в хранилище, проиграли — поставленные предметы сгорают.
- **Честность (provably fair)**: исход считается на сервере как
  `HMAC_SHA256(serverSeed, "clientSeed:nonce")`, приведённый к числу `[0, 1)`.
  Хеш серверного сида публикуется заранее, сид раскрывается при смене `clientSeed`,
  а `[serverSeed, clientSeed, nonce]` любого розыгрыша можно пересчитать через
  `GET /api/upgrade/verify` — получится тот же `roll`.
- **Админка**: статистика (RTP, оборот, пользователи), начисление/списание монет,
  бан игроков, добавление предметов и правка цен каталога на ходу.

Экономика живёт в `data/store.json` (ключ — SteamID64), поэтому не требует никакой БД.

## Скины на сервере (серверный скинченджер)

Панель выдаёт игровому плагину набор скинов по SteamID:

```
GET /api/plugin/loadout/{steamId64}   + заголовок X-Plugin-Key
→ { weapons: [{def, paint, wear, seed, statTrak, kills, weapon}], knife, gloves, agentCt, agentT, music }
```

- `def` — item definition index (AK-47 = 7, Karambit = 507, Sport Gloves = 5030),
- `paint` — paint kit index (Redline = 282, Dragon Lore = 344).

Оба числа уже лежат в каталоге, подставлять руками ничего не надо.
Ключ плагина берётся на вкладке «Настройки» (кнопка «новый ключ») либо задаётся общий `PLUGIN_API_KEY`.

На вкладке **«Экипировка»** игрок надевает купленные скины по слотам (оружие, нож, перчатки,
агенты, музыка), задаёт износ, seed и StatTrak. Серверный плагин
`cs2-server/plugins/PanelSkins` (CounterStrikeSharp) забирает этот набор и красит оружие
**на стороне сервера** — клиент CS2 не модифицируется.

## Каталог своих предметов

- `data/catalog.sample.json` — каталог на 3 737 предметов: цены в монетах, реальные
  `def`/`paint` для серверного плагина и настоящие картинки предметов (с CDN Steam) —
  в карточках, ячейках рулетки и истории.
- Положите свой `data/catalog.json` с тем же форматом — панель подхватит его при старте.
- Всё добавленное и изменённое админом через админку хранится в `data/store.json`
  поверх файла каталога.

Формат элемента:

```json
{ "id": "skin-4f8d99d09ded", "weapon": "AWP", "pattern": "Dragon Lore (Souvenir)",
  "category": "Винтовки", "rarity": "covert", "price": 6400,
  "def": 9, "paint": 344, "float": [0.0, 0.7], "collection": "", "image": "https://..." }
```

`def` и `paint` нужны серверному плагину; `image` — картинка предмета в интерфейсе.
Данные по предметам взяты из открытого датасета [ByMykel/CSGO-API](https://github.com/ByMykel/CSGO-API) (MIT).

## Деплой на выделенный сервер

```bash
sudo useradd -r -s /bin/false cs2
sudo mkdir -p /opt/cs2-panel && sudo chown cs2:cs2 /opt/cs2-panel
sudo -u cs2 git clone https://github.com/Relog404/relog.github.io.git /opt/cs2-panel
cd /opt/cs2-panel/panel && sudo -u cs2 npm ci --omit=dev
sudo -u cs2 cp .env.example .env && sudo -u cs2 nano .env     # обязательно PUBLIC_BASE_URL и SESSION_SECRET
sudo cp deploy/systemd/cs2-panel.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now cs2-panel
```

Дальше — nginx как обратный прокси (`deploy/nginx/cs2-panel.conf`) и HTTPS через certbot.
Примеры команд и ограничение `/api/admin/*` по IP — внутри конфига.

Панель и игровой сервер могут жить на разных машинах: панель ходит к CS2 по RCON,
так что можно держать сайт на одном VPS, а сервер — на другом.

## Безопасность

- RCON-пароли не уходят на фронтенд (в ответах только `hasPassword`).
- Управление и админка — только для SteamID из `ADMIN_STEAM_IDS`.
- Опасные RCON-команды (`rcon_password`, `quit`, `_restart`, …) требуют подтверждения.
- Сессии — cookie с HMAC-подписью, `httpOnly`, `secure` при https.
- `.env` и пользовательские данные не попадают в git (см. `.gitignore`).
- Реальных денег и реальных предметов в контуре нет — значит, нечего красть и не на что жаловаться.
